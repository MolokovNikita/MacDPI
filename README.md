# MacDPI

Приложение для macOS, которое помогает открыть YouTube и Discord там, где их
блокируют с помощью DPI. Работает локально, без VPN и внешних серверов:
трафик идёт напрямую к сервисам, MacDPI только меняет то, как первые пакеты
соединения выглядят для оборудования провайдера.

Требуется macOS 13 или новее. На macOS 26 интерфейс использует Liquid Glass.

## Установка

1. Скачайте [MacDPI 0.4.4 для Apple Silicon (M1/M2/M3/M4 и новее)](https://github.com/MolokovNikita/MacDPI/releases/download/v0.4.4/MacDPI-0.4.4-macos-arm64.zip)
   и распакуйте ZIP — внутри находится `MacDPI.app`.
   Все выпуски доступны в [GitHub Releases](https://github.com/MolokovNikita/MacDPI/releases).
   Готовая сборка предназначена для macOS 13+ на Apple Silicon (`arm64`);
   для Intel соберите приложение из исходников (см. «Сборка»).
2. Перетащите `MacDPI.app` в «Программы» или выполните из корня проекта:

   ```sh
   ditto build/MacDPI.app /Applications/MacDPI.app
   ```

3. Откройте MacDPI. При первом подключении macOS попросит пароль
   администратора, чтобы установить системный компонент. Само приложение
   пароль не видит и не хранит.

Чтобы обновить приложение, отключите соединение, завершите MacDPI через значок
в строке меню и замените `MacDPI.app` новой сборкой. Если изменился системный
компонент, macOS снова попросит разрешение при подключении.

Передавать приложение нужно целиком, в архиве:

```sh
ditto -c -k --sequesterRsrc --keepParent build/MacDPI.app build/MacDPI.zip
```

Сборка делается под архитектуру компьютера, на котором её запустили, и
подписывается локально (ad-hoc). На другом Mac система может заблокировать
запуск. Для распространения без этого нужны Developer ID и нотаризация.

## Использование

- **Подключение** — большая кнопка включает и выключает обход. Ниже видно,
  открываются ли YouTube и Discord после включения.
- **Настройки** — выбор режима обхода, сохранение диагностического отчёта и
  журнал событий. Для обычного использования оставьте «Автоподбор».

Если сервис был открыт до подключения, перезагрузите страницу или
переподключитесь к голосовому каналу: старые соединения могли остаться на
прежнем маршруте.

Окно можно закрыть, MacDPI останется в строке меню. Выход из приложения
выключает обход и восстанавливает настройки сети.

## Как это работает

- Приложение на SwiftUI управляет системным компонентом через защищённый
  Unix-сокет. Компонент работает от root (он нужен для настройки сети), само
  приложение работает от имени пользователя.
- Системный трафик попадает в виртуальный интерфейс `utun` и обрабатывается
  сетевым стеком gVisor через tun2socks. Исходящие соединения привязаны к
  физическому интерфейсу, чтобы не попасть обратно в туннель.
- В TCP-соединениях MacDPI дробит TLS ClientHello на записи и сегменты по
  выбранной стратегии. Шифрование не затрагивается: TLS остаётся сквозным,
  сертификаты не подменяются.
- Начиная с 0.4.4 UDP/443 (QUIC) передаётся напрямую. Перед распознанным
  QUIC Initial отправляются шесть подставных QUIC-пакетов с шаблоном Flowseal
  на том же UDP-сокете. Повторы ограничены тремя сериями с интервалом от
  500 мс; обычные зашифрованные датаграммы передаются без изменений.
  Распознаются Initial для QUIC v1 и v2. Обычный UDP/443, включая STUN,
  проходит без QUIC-фейков.
- Для голосовых соединений Discord распознаются discovery, STUN и RTP. Перед
  первым пакетом отправляется серия подставных датаграмм (шаблон Flowseal),
  ответы на них отбрасываются. Если голосовой поток долго не получает ответов,
  пробуется резервный STUN-профиль.
- DNS-запросы уходят через DNS-over-HTTPS. Прежние DNS-настройки сохраняются
  до изменения и восстанавливаются при отключении.
- Раз в две секунды проверяется физический интерфейс. При смене сети
  соединения переоткрываются, а привязка и DNS обновляются.

### Режимы обхода

| Режим | Что делает |
| --- | --- |
| Автоподбор | Проверяет полную загрузку страниц YouTube и Discord и выбирает режим отдельно для каждого сервиса; удачный вариант запоминается для сервера на 10 минут. Для серверов YouTube сначала пробуется Google seq-overlap (см. ниже) |
| TLS-запись + split | Делит ClientHello на две TLS-записи по имени сервера и отделяет первый байт в отдельный сегмент |
| TLS/TCP split по SNI | Делит ClientHello на TLS-записи и режет его на сегменты в нескольких местах, в том числе по имени сервера |
| TLS-запись | Только дробление на TLS-записи |
| General | Перекрытие по SEQ с шаблоном ClientHello, как в `general.bat` Flowseal. Экспериментальный |
| Fake TLS | Подставные ClientHello с неверными SEQ/ACK. Экспериментальный |
| Disorder | Первый сегмент отправляется не по порядку, как disorder в ByeDPI. Экспериментальный |

Пакетные режимы (General, Fake TLS) используют BPF на физическом интерфейсе и
пока работают только с IPv4 и Ethernet.

Некоторые видеосерверы YouTube (`*.googlevideo.com`) в проверенной сети не
ответили на настоящий ClientHello, хотя имя `www.google.com` на том же адресе
получило TLS-ответ. Для TCP в автоподборе первым пробуется Google seq-overlap:
перед настоящим ClientHello отправляется пакет с подставным ClientHello на
`www.google.com` (681 байт, шаблон Flowseal) за пределами принятой сервером
последовательности. Этот экспериментальный профиль помогает не на всех узлах.
QUIC обрабатывается отдельно и не требует успешного TCP-обхода к видеосерверу.

### Переход с предыдущих версий

После перехода с версии, блокировавшей QUIC, полностью перезапустите браузер:
он мог временно запомнить недоступность HTTP/3. Затем включите MacDPI и
откройте видео заново.

## Восстановление сети

При отключении удаляются только маршруты MacDPI, восстанавливаются DNS,
закрывается `utun`. Если приложение аварийно завершится, системный компонент
сам выключит обход. После перезапуска компонент восстанавливает DNS по журналу
и не включает обход повторно.

Изменения DNS, сделанные пользователем или другим приложением во время работы
MacDPI, не перезаписываются. Если уже работает другой VPN с маршрутом по
умолчанию через `utun`, MacDPI откажется подключаться, чтобы не создать петлю.

Установленные файлы:

| Путь | Назначение |
| --- | --- |
| `/Library/Application Support/MacDPI/macdpi-helper` | системный компонент |
| `/Library/LaunchDaemons/local.macdpi.helper.plist` | служба launchd |
| `/Library/Application Support/MacDPI/dns-backup.json` | журнал для восстановления DNS |
| `/Library/Application Support/MacDPI/diagnostics.jsonl` | журнал компонента (до 2 МБ, два архива) |
| `~/Library/Logs/MacDPI/app.log` | журнал приложения (до 256 КБ) |
| `/var/run/macdpi-<UID>.sock` | управляющий сокет, доступен владельцу и root |

Удалить системный компонент (сначала закройте приложение):

```sh
sudo ./scripts/uninstall.sh
```

Компонент удаляется только после успешного восстановления DNS.

## Диагностика

«Сохранить отчёт…» в настройках собирает журналы приложения и компонента в
один `.txt`. В отчёт попадают версии, маршруты, DNS, выбранные стратегии,
адреса, порты и этапы соединений. Содержимое страниц, HTTP-заголовки, пароли и
звук не записываются. Отчёт можно сохранить и после отключения.

Проверить пакетные режимы без изменения маршрутов и DNS. После аргументов можно
перечислить видеосерверы из отчёта: для каждого будут сравнены `multisplit` и
Google seq-overlap.

```sh
sudo build/MacDPI.app/Contents/Resources/macdpi-daemon --packet-probe --interface en0 rr5---sn-q4flrnes.googlevideo.com
```

## Ограничения

- Помогает только против DPI. При блокировке по IP-адресу этого может быть
  недостаточно.
- Если UDP/443 полностью недоступен у провайдера, обработка QUIC не заменяет
  рабочий TCP-путь к конкретному видеосерверу.
- Сети только с IPv6, без IPv4-маршрута по умолчанию, не поддерживаются.
- Нет подбора TTL под расстояние до DPI и запасного пути через внешний сервер.

## Сборка

Нужны Command Line Tools (Swift), Python 3 и Go 1.27.1+. Скрипт ищет Go в
`.tools/go`, иначе можно указать путь явно: `GO_BIN=/path/to/go`.

```sh
./scripts/build.sh
```

Результат — `build/MacDPI.app`. Иконка лежит в `macos/AppIcon.icns`;
перерисовать её можно командой `swift scripts/make_icon.swift macos/AppIcon.icns`.

Тесты движка:

```sh
cd daemon
go test -race -timeout 45s ./...
go vet ./...
go test -run '^$' -fuzz FuzzSNI -fuzztime 5s
```

Если Go находится в `.tools/go`, замените `go` в командах тестирования на
`../.tools/go/bin/go`.

Тесты не требуют root и не меняют настройки сети. Проверки с реальной сетью
запускаются отдельно:

```sh
cd daemon
MACDPI_PHYSICAL_SMOKE=en0 go test -race -run TestPhysicalAdaptiveHTTPS -v -timeout 70s
MACDPI_PHYSICAL_MATRIX=en0 go test -run TestPhysicalStrategyMatrix -v -timeout 15s
```

## Структура

| Каталог | Содержимое |
| --- | --- |
| `macos/` | приложение на SwiftUI и Network Extension (запасной вариант, требует профилей Apple Developer) |
| `daemon/` | системный компонент и сетевой движок на Go |
| `scripts/` | сборка, генерация Info.plist и иконки, удаление компонента |
| `reference/flowseal/` | источники, закреплённый коммит и контрольные суммы шаблонов |
| `daemon/patterns/` | встроенные шаблоны пакетов для сетевого движка |

## Лицензии

tun2socks (MIT) и gVisor (Apache 2.0) подключены как Go-модули с
зафиксированными версиями. Их лицензии копируются в
`MacDPI.app/Contents/Resources/Legal/` при сборке. Алгоритмы UDP-desync
сверялись с [ByeDPI](https://github.com/hufrea/byedpi), разбор голосовых
соединений — с [документацией Discord](https://github.com/discord/discord-api-docs/blob/main/developers/topics/voice-connections.mdx).
Шаблоны пакетов взяты из Flowseal и находятся в `daemon/patterns/`; источник,
закреплённый коммит и контрольные суммы — в `reference/flowseal/SOURCE.json`.
Пути в этом файле относятся к исходному репозиторию Flowseal.
